## Behaviour

`create_batch -> approve_batch -> export_batch -> mark_processed`; `cancel_batch` before export; `return_line` after a bank return.

- **No double pay:** `PayoutBatchLine.is_open` + partial unique constraint on `teacher`; batch building locks the tutor's `User` row, skips anyone with an open line, and the amount is the ledger 2020 balance minus open lines. Closed lines (paid, returned, skipped, cancelled) release the tutor.
- **Maker-checker:** the creator can neither approve nor mark processed (`maker_checker_violation`, HTTP 403). Not a setting. With a single admin the workflow cannot finish; that is intended.
- **Re-checks:** approve re-compares each line's bank-account fingerprint (sha256 of the stored ciphertext, so any re-save counts as a change) and the ledger balance; export re-compares the account. A failing line becomes a visible `skipped` line with a reason and a failed `PayoutAttempt`; if nothing is left the call is refused (`no_payable_lines`) after committing the skips. `mark_processed` re-checks balances and refuses the whole batch (`balance_changed`) rather than posting a short line.
- **Skipped lines instead of silent drops:** unreadable bank details (`bank_details_unreadable`), details changed in the last `PAYOUT_BANK_CHANGE_HOLD_HOURS` (72) (`bank_details_changed_recently`). Balances under `PAYOUT_MIN_ZAR` (100) carry over and are only counted (`carried_over_count`).
- **CSV:** admin + password re-entered, `Cache-Control: no-store`, one `PayoutExportAudit` row per download (rows + sha256 of the bytes), cells starting `= + - @` (after leading spaces), tab or CR get an apostrophe prefix. Columns: Beneficiary Name, Account Number, Branch Code, Account Type, Bank, Amount (ZAR), Beneficiary Reference, Own Reference. Branch codes are the universal ones the payout-settings serializer already enforces for the 8 supported banks.
- **Ledger:** one atomic transaction in `mark_processed`; one DR 2020 / CR 1030 journal (ZAR, user = the tutor) per exported line; a repeated call returns the processed batch and posts nothing; the DB constraint backstops a replay. A bank return posts the reversing DR 1030 / CR 2020 (`payout_returned`).
- The legacy `payouts/execute-batch/` stays 503, `payouts/batch/` stays the read-only preview (now using `payable.py`).

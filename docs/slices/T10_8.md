# Task 10.8: receipts

Branch: `feature/claude-financial-core`. ERR block: integrator 510.

- `Receipt` (one per successful `PaymentTransaction`, `OneToOne`) and `ReceiptSequence` (one locked counter row per month): numbers are `INV-YYYYMM-XXXXX`, gap-free per month.
- `apps/payments/services/receipts.py::issue_receipt` is idempotent and is called from exactly one place, the `post_save` hook in `apps/payments/signals.py`, so every path that marks a payment `SUCCESS` (webhook, PayPal capture, grace clearance, reconciliation, credit purchase) issues a receipt in the same transaction. A payment that never reaches `SUCCESS` (pending, failed, unallocated) has none.
- Money: captured amount in its own currency; `PLATFORM_VAT_RATE` (default 0, D-12) splits a VAT-inclusive total into subtotal and tax. The PDF (reportlab, added to `requirements.txt`) is rendered on demand; `pdf_storage_key` is reserved and unused.
- API: `GET /api/v1/payments/receipts/` (own receipts, exact money strings) and `GET /api/v1/payments/receipts/<id>/pdf/` (404, not 403, for anyone else's id; `Cache-Control: private, no-store`).
